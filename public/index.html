ENGINEERING HISTORY / EVIDENCE SYSTEM

Understand how a codebase changed. With proof.

Project Autopsy reconstructs a software project's engineering history from observable repository, runtime, deployment, schema and test evidence. The product keeps facts, derived signals and interpretation separate so developers can inspect the basis of every conclusion.

EVIDENCE MODEL

Facts first. Interpretation downstream.

Autopsy keeps repository observations, runtime observations and derived interpretation in separate layers. That distinction is part of the product, not a footnote.

OBSERVE
Git, structure, schema, tests

Commit history, file churn, architecture surfaces, dependency changes, complexity, coupling, migrations and changed-test evidence.

RECONCILE
Runtime & deployment

Observed telemetry and deployment records can be inspected alongside explicit repository revisions without pretending correlation is causation.

EXPLAIN
Report & grounded insights

Reports, interview scaffolds and interpretation remain bounded by the evidence snapshot they were generated from.
